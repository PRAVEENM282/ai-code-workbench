## Review #2 — Architecture

- C4 context/container, component, request sequence, persistence/data-flow, and security-boundary diagrams are in `ARCHITECTURE.md`.
- API handlers delegate to an application service; routing, prompt management, provider adapters, analysis, persistence, and telemetry have separate seams.
- Provider interfaces, YAML configuration, and compatible API adapters keep deployment and provider choice out of domain policy.
- Queue/worker work is documented as a future dispatcher adapter, not an undeclared V1 dependency.
- Raw provider observations roll into idempotent hourly/daily aggregates; cache remains disabled by default; response size and compression limits are configurable.

Verification: backend unit/integration-style tests pass; a fresh Docker Compose image build/start succeeded after adding Alembic revision `0002_open_language_names`, and the database-backed API health check returned successfully.

## Review #4 — Security

- Requests are schema-validated and bounded; analyzer subprocesses use fixed argument arrays, private permission-restricted temporary files, configured timeouts, sanitized environments, output normalization limits, and cleanup; submitted code is not executed. The subprocess inherits the API container network namespace and is bounded by container resource limits.
- Provider endpoints are operator configuration, host-allowlisted, HTTPS-only except explicitly configured Ollama, and redirects are disabled. Secrets remain server-side.
- SQL uses SQLAlchemy parameterized expressions; browser output is rendered through React text handling; CSP/security headers, in-memory rate limiting, correlation-aware redacted logs, and restricted Compose capabilities are configured.
- Cookie-authenticated CSRF protection is not applicable to the current no-auth, no-cookie shared workspace; secure cookie settings are required before adding such a flow.
- Dependency audits, Trivy filesystem scan, and CycloneDX SBOM generation are present in CI but not run here. Compose image-level scan is therefore also unverified.

Security limitation to retain: provider host allowlisting prevents arbitrary user-selected URLs, but it is not a complete defense against an operator configuring a trusted hostname whose DNS later resolves to a private/metadata address. Deployments should use controlled egress/DNS policy; DNS pinning/egress proxying is a future hardening item.
